# Contracts registry

Canonical, machine-readable contracts for AegisShield AI. Every contract has exactly one owner and one reviewer. Current version: **1.1.1** (30 Oct 2026, owner metadata only). 1.1.0 added the early-warning contract and remapped owners to the v2 team split; 1.1.1 moves the data pipeline to Member 1. Plan hashes and `input_snapshot_id` are unchanged from 1.0.0.

Member numbers follow the v2 team split in `docs/00-source-of-truth.md` §7 (M1 data pipeline, sensing and early warning; M2 UI/UX and frontend; M3 RAG, contracts and decisions; M4 backend and deterministic engine; M5 pitch). They do **not** match the retired v1 role documents.

Run before every merge:

```bash
pip install "jsonschema>=4.18" pyyaml openapi-spec-validator
python3 tools/check_contracts.py
```

## Conventions (summary of `docs/00` §9.1)
- JSON Schema draft 2020-12. Schemas reference each other by **relative file name** (no `$id`), so tooling resolves them from disk.
- Money is integer whole rupees (`*_inr`); rates are in basis points (`*_bps`); rounding is half-up per line.
- Dates are `YYYY-MM-DD` (Asia/Kolkata business dates); timestamps are RFC 3339 with offset; `effective_to` is inclusive.
- Nullable fields are always present; empty lists are `[]`.
- Every payload carries `schema_version`. Existing 1.0.0 fixture files keep `"1.0.0"` on purpose, because changing them would change `input_snapshot_id` and every plan hash.
- Golden comparisons ignore these keys anywhere: `created_at`, `updated_at`, `started_at`, `finished_at`, `completed_at`, `decided_at`, `occurred_at`, `duration_ms`, `generated_at`, `reset_at`, `prev_hash`, `event_hash`.
- `plan_hash` covers exactly `plan_hash_material` (described in `plan.schema.json#/$defs/RecoveryPlan`). `input_snapshot_id` is the SHA-256 of the canonical JSON of the **twelve plan-input fixture files** keyed by file stem. `external_signals.json` is deliberately excluded because early warnings never change plans.

## Changing a contract
1. Edit schema, examples, fixtures and `CHANGELOG.md` in one pull request.
2. If behaviour changed, Member 3 regenerates goldens with `--write-golden`, and the reviewer checks the diff line by line.
3. The checker must be green and the reviewer must approve; tag the consumers.
4. From Sat 31 Oct 2026 only patch changes are allowed; from Sun 1 Nov 20:00 (feature freeze) only fixes Member 3 approves. Every change needs an entry in the decision log (`docs/00` §20).

## Type generation hints
- Frontend: bundle first (`npx @redocly/cli bundle contracts/openapi.yaml -o build/openapi.bundled.yaml`), then run `npx openapi-typescript build/openapi.bundled.yaml -o frontend/src/api/schema.d.ts`.
- Backend: `datamodel-codegen --input contracts/schemas --input-file-type jsonschema --output backend/app/models/generated --output-model-type pydantic_v2.BaseModel`. If that fails, hand-write the models and validate them in tests.
